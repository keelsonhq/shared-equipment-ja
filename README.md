# 共有機材管理

[Keelson](https://keelson.dev) のテンプレートアプリです。Keelson にデプロイすると、ログイン・社員の一覧・データベース・
添付ファイルの保存先・毎朝の返却の通知の定期実行を Keelson が用意するので、secret の設定なしで使い始められます
(社員の一覧は下の「Keelson で動かす」の手順で Directory を有効にし、通知のメールを送るときだけ Webhook を設定します)。

Keelson でしか動かないアプリではありません。中身はふつうの SvelteKit(Node.js)アプリで、手元では `pnpm dev` だけで動きます。
ほかの環境で運用するときは、Keelson が受け持っている「ログイン」「社員の一覧」「通知の定期実行」を、自社の仕組みにつなぎ替えてください
([CUSTOMIZE.md](./CUSTOMIZE.md) の「Keelson 以外で動かす」)。

---

検証用スマホ・共用 PC・プロジェクター・撮影機材など、**みんなで使う機材**の予約と貸出・返却を記録する台帳アプリです。
「いつ空いているか」「いま誰が持っているか」「返ってきたか」がひと目で分かります。

- **7 日の空き状況が一覧で分かる** — 機材の一覧の 1 列に、今日から 7 日分の予約と貸出の帯が並びます。
  空いている時間を探して、その場で予約できます
- **予約は重ならない** — 同じ機材の予約は時間が重なると取れません(終了の時刻ちょうどからは次の人が取れます)。
  同時に 2 人が同じ枠を予約しても、データベースの段階で 1 件だけが成立します
- **予約と実際の貸出を分けて記録** — 予約の時間になったら「借りる」で貸出を記録します。予約なしの飛び込みでも借りられ、
  返却予定は次の人の予約の前までに抑えられます
- **返さないまま次の人に渡らない** — 返却予定を過ぎても自動で返却済みにはしません。前の利用者が返すまで次の人には貸し出せず、
  次の予約者の画面に「前の利用者が未返却です」と出ます
- **QR 付きの資産タグ** — 機材ごとに QR コード付きのラベルを印刷できます。スマホのカメラで読み取ると、その機材のページ
  (借りる・返却・予約)が開きます(ログインが必要です)
- **返却の通知** — 毎朝、本日が返却予定の人と、返却予定を過ぎている人に知らせます(メールへ中継する Webhook を 1 つ用意すれば通知できます)。
  通知を設定しなくても、期限はホームの一覧で確認できます
- **管理者のホームで日々の作業** — 本日の返却予定・期限超過・本日の予約・いま空いている機材の数と、対応が必要な機材(期限超過・
  次の予約が迫っている貸出中・利用停止)が並びます
- **記録が残る** — 登録・編集・予約・取消・貸出・延長・返却・利用停止・再開・CSV 取込をすべて履歴に残します。
  本人の返却は「返却済」、管理者が代わりに記録した返却は「回収済」の朱印で示します
- **AI アシスタントから使える** — Claude や ChatGPT に「いま空いている iPhone はある?」「CM-0001 を明日 13 時から予約して」と
  話しかけるだけで、空きの確認・予約・貸出・返却ができます(MCP。下の「AI アシスタントから使う」)
- **社員は Keelson のメンバー** — アプリ独自の社員台帳や社員登録はありません

使っている様子は、テンプレート紹介ページの動画で確認できます。デプロイしたアプリは空の台帳から始まります
(機材の種類と保管場所の初期値だけが入っています)。

## Keelson で動かす

このフォルダで `keelson deploy` を実行すると、Keelson にデプロイできます(Keelson CLI は
`curl -fsSL https://keelson.dev/install.sh | sh` で入ります)。**secret の設定は不要です**(返却の通知を使うときだけ、下の「通知の設定」)。

### 導入手順

1. **社員一覧(Directory)を有効にします。** 管理者が社員の代わりに予約・貸出を記録するときに、ワークスペースのメンバーから選ぶために必要です
   (自分の予約・貸出・返却は、有効にしなくても使えます)。
   ```bash
   keelson apps directory enable
   keelson deploy
   ```
   有効にしただけでは反映されません。再デプロイすると、アプリにメンバー一覧を読むためのトークンが渡されます
   (アプリのサーバー側だけで使い、ブラウザには渡しません)。メンバーのプロフィール画像もここから取ります
   (画像が無い人は頭文字で表示します)。詳しくは Keelson ドキュメントの
   [ログイン中のユーザー情報を使う](https://keelson.dev/ja/docs/building-apps/using-identity/) を参照してください
2. **管理者を決めます。** このアプリの管理者は、Keelson でアプリの `manage` 権限を持つ人です
   (既定では Owner / Admin / Developer)。機材の登録・利用停止、全員の予約と貸出の確認、代理の予約・貸出・回収、CSV 取込、マスタ管理ができます。
   それ以外の人(`view` のみ)は、機材の一覧・予約・自分のページを使います。権限はコンソールの
   [グループとアプリ権限](https://keelson.dev/ja/docs/workspace/groups-and-app-access/) で変えられます
3. **マスタ管理** で機材の「種類」と「保管場所」を自社に合わせて整えます
4. ホームの「機材を登録」で機材を登録します。既存の台帳があれば「CSV で取り込む」でまとめて登録します
   (ひな形 CSV は取込画面からダウンロードできます)
5. 機材のページの「ラベルを印刷」で QR 付きのラベルを印刷し、機材に貼ります
6. 必要なら、返却の通知を設定します(下の「通知の設定」)

### 通知の設定

毎朝 9:00(ワークスペースのタイムゾーン)に、返却の通知のジョブ `return-reminder` が動きます。

- 送る相手と内容: 本日が返却予定の貸出の借り手へ「本日が返却予定です」、返却予定を過ぎた貸出の借り手へ「返却予定を過ぎています」。
  同じ通知は 2 回送りません(ジョブをもう一度実行しても重複しません)。返却予定を延長すると、新しい返却予定についてまた送ります。
  期限超過の通知は返却予定ごとに 1 回です
- 送り方: **メールへ中継する Webhook を 1 つ用意すれば通知できます。** アプリはその URL に、1 通ずつ次の JSON を `POST` します。
  ```json
  { "to": "taro.yamada@example.com", "subject": "…", "text": "…" }
  ```
  受け取った側でメールとして送ってください(社内の自動化ツールや、メール送信の API を呼ぶ小さな関数など)。
- 設定: Keelson のコンソールで、このアプリの secret に `NOTIFY_WEBHOOK_URL`(必須)と `NOTIFY_WEBHOOK_TOKEN`(任意。
  `Authorization: Bearer <token>` として送ります)を設定し、再デプロイします
- 確かめ方: コンソールのジョブの画面で「今すぐ実行」し、ログに `sent N` が出ることを確かめます。未設定のときはログに
  「送るべきだった件数」が出るだけで、何も送りません。送信に失敗した通知は記録され、次の実行で再試行されます(5 回まで)。
  失敗があった回のジョブは失敗として終わるので、コンソールの実行履歴で気付けます。
  ホームの「要対応」に、通知を送ったか(送信済 / 送信失敗)が出ます
- 通知の宛先は、借りたときのメールアドレスです

### データベースの更新(migration)

デプロイのたびに、新しい版が動き始める前に `node scripts/migrate.mjs` が 1 回だけ実行され、
`migrations/` の未適用の SQL がデータベースに適用されます(`keelson.yaml` の `db.migrate`)。
失敗するとデプロイは失敗し、それまでの版が動き続けます。手元(ローカル)ではアプリの起動時に同じ処理が走ります。

### 任意の設定

| 変えたいこと                                                | 方法                                                          |
| ----------------------------------------------------------- | ------------------------------------------------------------- |
| 「今日」「いま」の基準になるタイムゾーン(既定 `Asia/Tokyo`) | `keelson.yaml` の `env:` に `APP_TIME_ZONE`(運用を始める前に) |
| 通知の時刻                                                  | `keelson.yaml` の `crons` の `schedule`                       |

## AI アシスタントから使う(MCP)

Claude や ChatGPT などの AI アシスタントをこのアプリにつなぐと、話しかけるだけで台帳を照会・操作できます。
AI アシスタントとのやりとり(MCP)とログイン(OAuth)は Keelson が受け持ち、アプリは `keelson.yaml` の `mcp:` に宣言した
ツールを `POST /api/mcp/<ツール名>` で受けるだけです。

- **接続先の URL**: `https://<アプリの URL>/mcp`
- **Claude Code**: `claude mcp add --transport http shared-equipment https://<アプリの URL>/mcp` で追加し、Claude Code の `/mcp` から
  認証します。ブラウザに Keelson の同意画面が開くので、内容を確かめて許可します
- **claude.ai / ChatGPT**: 設定のコネクタの追加で上の URL を貼ります。Keelson の同意画面で許可すると使えるようになります

接続の手順と同意画面の細部は Keelson 側の提供状況によって変わることがあります。最新の手順は Keelson のドキュメントを確認してください。

話しかけ方の例:

- 「いま空いている iPhone はある?」
- 「鈴木さんが今日からデバッグ用の Pixel を借ります。返却は金曜」
- 「CM-0001 を明日 13 時から 15 時まで予約して」
- 「借りている三脚を返した」
- 「PJ-0002 は故障で利用停止にして」

できること:

| 操作                                                           | 使える人                                 |
| -------------------------------------------------------------- | ---------------------------------------- |
| 機材を探す・1 台の詳細・自分の貸出と予約・種類と保管場所の一覧 | 全員                                     |
| 借りる・返却・返却予定の変更・予約・予約の取消                 | 全員(自分の分。ほかの人の分は管理者だけ) |
| 機材の登録・利用停止・利用の再開                               | 管理者(`manage`)だけ                     |

- AI アシスタントからの操作も、画面と同じ規則と権限で動きます(他人の予約の取消や、一般の社員の機材登録はできません)。
  操作は接続した本人の名前で履歴に残ります。
- 人は名前かメールアドレスで指定できます。同じ名前の人が複数いるときは、AI アシスタントが候補を示して聞き返します。
- 日時を省くと、貸出の返却予定は今日の 18:00、予約は次の 15 分枠から 1 時間になります。
- 接続(どの AI アシスタントに許可したか)は Keelson のコンソールで確認でき、ワークスペースの管理者は接続を失効させられます。
- ローカル(`pnpm dev`)には MCP の入口がありません。ツールの動きは `curl` で直接確かめられます:
  ```bash
  curl -s -X POST http://localhost:5173/api/mcp/find_equipment \
    -H 'content-type: application/json' -d '{"q":"iPhone","status":["available"]}'
  ```

## ローカル開発

```bash
pnpm install
pnpm dev
```

これだけで、画面・API・HMR・サンプルデータが 1 つの URL(既定 `http://localhost:5173`)でまとめて起動します。
ビルドや `.env` の作成は不要です。

`pnpm dev` は Keelson CLI(v0.6.11 以降)の `keelson dev serve` の後ろでアプリを動かします。`keelson dev serve` は
本番のゲートウェイと同じログイン情報(`X-Keelson-User-*` ヘッダ)を付けてリクエストを転送し、社員一覧(Directory)の
代わりも務めるローカル用の入口です。ログインする人と社員の一覧は、名簿ファイル
[`seed-data/dev-users.json`](./seed-data/dev-users.json) の人たちです(先頭の「(サンプル)山口」が管理者、ほかは一般の社員)。
詳しくは公開ドキュメントの [ローカルで動かす](https://keelson.dev/ja/docs/building-apps/local-development/) を参照してください。

- **利用者の切り替え**: `http://localhost:5173/__keelson/dev` を開いて名簿の人を選ぶと、その人として画面を表示します
  (再起動は不要)。一般の社員を選ぶと管理メニューは出ず、管理 API は 403 になります。「(サンプル)佐藤」は借りている機材と予約がある状態です。
- 最初から別の人で始めるときは `pnpm dev -- --as sample-sato` のように名簿の ID を渡します。
- 切り替えはブラウザごとです。2 人で予約と貸出を試すときは、同じ `pnpm dev` を別々のブラウザ(またはシークレットウィンドウ)で開き、
  片方だけを `/__keelson/dev` で一般の社員に切り替えます。
- CLI を入れていないときは `pnpm dev` が警告を出し、名簿の管理者 1 人として起動します(利用者は切り替えられません。
  社員の一覧は同じ名簿です)。CLI は `curl -fsSL https://keelson.dev/install.sh | sh` で入ります。

サンプル(機材 25 件と、今日を挟む予約・貸出)は、ローカルのデータベースが空のときに `pnpm dev` が入れます
(空のまま始めたいときは `LOCAL_SAMPLE_DATA=0 pnpm dev`)。

`pnpm dev` は開発専用の入口です。デプロイと同じ動きの `pnpm start`(`pnpm build` のあと)は
プラットフォームのログイン情報が無いリクエストを 401 で拒否し、サンプルデータも入れません。

- データベースは libSQL。ローカルではファイル(`local.db`)を使うので、追加の設定なしで全機能が動きます。
- 添付ファイルはローカルでは `.keelson/files` に保存されます。
- ローカルの QR コードは、開いているアドレス(`http://localhost:5173` など)を指します。デプロイしたアプリではアプリの URL を指します。
- 返却の通知のジョブは `node src/lib/server/jobs/return-reminder.ts` で手で動かせます(`local.db` が対象。
  `NOTIFY_WEBHOOK_URL` を指定しなければ、送るべき件数をログに出すだけです)。

品質チェック(フォーマット + lint + テスト + 文言規約)は 1 コマンドです:

```bash
pnpm check
```

ブラウザで基本操作を通して確かめる e2e テスト(Playwright)もあります。`pnpm check` には含まれません。
仕組みと書き方は [AGENTS.md](./AGENTS.md) の「e2e」にあります。

```bash
pnpm e2e:install   # 初回(と Playwright を上げたとき)だけ。テスト用の Chromium を入れる
pnpm e2e           # 一時的なデータベースで起動して確かめる(pnpm dev を起動したままでも動く)
```

e2e は一般の社員の操作も確かめるため、Keelson CLI(`keelson dev serve`)が必要です。CLI が無いときは、
入れ方を示すエラーを出してテストを始めずに終わります。

## 制限と注意点

導入前に次の前提を確認してください。多くは [PROMPTS.md](./PROMPTS.md) の改修例で調整できます。

- **誰がいつ使うかは全員に見えます。** 共有の機材なので、一般の社員にも、各機材の予約と貸出の期間と利用者の名前を表示します。
  予約の目的・貸出の備考・過去の利用の記録(自分以外)・機材の製造番号や備考は、管理者と本人だけが見られます(他人の分を見る機能はありません)。
  管理者(`manage`)は全員分の予約・貸出・履歴・添付を閲覧・操作できます。
- **時刻は 15 分単位です。** 予約の開始・終了と返却予定は :00 / :15 / :30 / :45 で指定します。予約は 1 回 30 日までです。
  貸出と返却の時刻は、記録した時刻になります(後から時刻を入力・訂正する機能はありません)。
- **返却は自動では記録されません。** 返却予定を過ぎた貸出は「期限超過」として残り、返却を記録するまで次の人に貸し出せません。
  機材が手元に戻っていたら、管理者が「返却を記録」してください(「回収済」になります)。
- **時刻はアプリのタイムゾーン(既定 `Asia/Tokyo`)で扱います。** 夏時間のあるタイムゾーンでは、切り替え前後の時間帯の予約が正しく扱えないことがあります。
  運用を始めた後に `APP_TIME_ZONE` を変えないでください(記録済みの時刻の意味がずれます)。
- **通知は返却予定の当日と、超過した後の 1 回だけです。** 前日の通知や、超過中の毎日の再通知はありません。通知にはメールへ中継する Webhook が必要です。
- **社員一覧(Directory)を有効にするまで、ほかの人の代わりに予約・貸出を記録できません。** 自分の予約・貸出・返却は使えます。
  一覧を読めないときは、社員を選ぶ欄に「社員の一覧を取得できませんでした。」と表示されます。
- **CSV 取込は機材の登録だけです。** 予約・貸出は取り込めません。既に登録されている管理番号の行は取り込みません。1 回 2,000 行・2 MB まで。
- **個数管理はしません。** 1 機材 = 1 行です。付属品は備考に書いてください。
- **予約の承認・繰り返し予約・予約の変更はありません。** 変えたいときは取り消して取り直します。
- **添付は 1 ファイル 10 MB まで・1 機材 20 件まで**、形式は PNG / JPEG / WebP / PDF です。添付は全員が開けます(写真・取扱説明書向け)。
- **AI アシスタント(MCP)が一度に受け取る一覧は 50 件までです。** 件数が多いときは、キーワードや状態で絞り込むよう頼んでください。
  書き込みの結果が分からなかった(時間切れなど)ときは、AI アシスタントは自動で再実行しません。機材の状態を確かめてから頼み直してください。
- **機材は削除できません。** 使わなくなった機材は「利用停止」にします(履歴を残すため)。
- **データベースの変更は `migrations/` の SQL ファイルだけで行います。** 適用済みのファイルを書き換えると、起動とデプロイが止まります(CUSTOMIZE.md)。
